# Vertical Rules — `frontend/` (React + TypeScript + Three.js Operator UI)

> **Seam Counterpart:** `backend/` (via `api-spec/openapi.json` & `src/api/schema.ts`)

## 1. Typed API Client & Contract Discipline

- **Use `src/api/schema.ts`, `src/api/httpClient.ts`, `src/api/index.ts`, and `src/api/services/`:** All API calls go through the typed client backed by `api-spec/openapi.json`. `src/api/schema.ts` is generated by `openapi-typescript`—regenerate it when `openapi.json` changes and never hand-edit it or invent field/enum names.
- **Coordinate order & wind convention:**
  - GeoJSON polygons/lines (`perimeters`, `vectors`, `roads`, `waterways`) use `[lon, lat]`; point objects (`LatLon`) use `{lat, lon}`.
  - `windFromDeg` is the meteorological direction wind blows **from** (0° = from North, blowing South). Ensure 3D layers in `src/engine/layers/` and `src/components/viewport/` follow this convention.

## 2. Async Simulation Polling & Error Resilience

- **Handle all `SimulationStatus` states (`queued`, `running`, `succeeded`, `failed`, `cancelled`):**
  When polling `GET /simulations/{id}` (or using `Prefer: wait=<seconds>`), stop polling immediately on `succeeded`, `failed`, or `cancelled`. If `status === "failed"`, surface `error.message` / `error.code` cleanly in the UI without crashing the 3D viewport.
- **Capability gating:** Respect `GET /capabilities` so unsupported engine toggles are disabled in the UI rather than triggering `422 unsupported_capability`.
